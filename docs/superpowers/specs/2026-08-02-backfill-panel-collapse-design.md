# 补采模块收放功能设计

## 目标

为“过去 24 小时补充采集”模块增加收起与展开能力。用户不查看明细时，模块压缩为一条紧凑状态栏，不再占用四个平台明细列表的页面高度。

## 交互行为

- 页面首次读取到已结束的补采任务时，模块默认收起。
- 收起状态约 42px 高，显示模块名称、任务结果、新增数量、结束时间和“查看明细”按钮。
- 点击“查看明细”后显示当前完整标题区、错误提示和逐来源明细，按钮改为“收起明细”。
- 用户主动启动补采时自动展开。
- 页面恢复到正在运行的补采任务时自动展开。
- 补采发生读取或运行错误时自动展开，确保错误不会被隐藏。
- 补采完成后保持展开，供用户立即查看结果；用户可随后手动收起。
- 页面刷新后不恢复上次的手动选择，重新按上述默认规则决定状态，不使用 `localStorage`。

## 页面结构

- 保留现有 `backfill-panel` 容器和完整展开布局。
- 新增收起状态栏，视觉采用已确认的方案 B：极窄独立状态条。
- 收起时不渲染完整标题区、错误提示和来源列表，避免保留不可见高度。
- 展开/收起按钮提供 `aria-expanded` 和 `aria-controls`，受控区域具有稳定的 `id`。
- 窄屏状态栏允许内容换行，但按钮保持清晰可点击，不产生横向滚动。

## 状态规则

- 新增组件状态 `backfillExpanded`，初始值为 `false`。
- `startBackfill` 成功启动或恢复运行任务后，将其设为 `true`。
- 读取到 `running` 状态或设置 `backfillError` 时，将其设为 `true`。
- 任务从 `running` 变为结束状态时不自动收起。
- 用户按钮仅切换 `backfillExpanded`，不影响补采任务和轮询状态。

## 错误处理

- 没有补采任务且没有补采错误时，整个模块继续不显示。
- 有补采错误但没有任务时，收起摘要显示“补采状态异常”，模块自动展开并展示现有错误内容。
- 收放操作不发起请求，不能改变或清除错误状态。

## 验收标准

1. 已结束任务首次加载时只显示紧凑状态栏，来源明细不占页面高度。
2. 点击按钮可展开和再次收起明细，按钮文本和 `aria-expanded` 同步变化。
3. 新启动任务和恢复中的任务自动展开。
4. 任务完成后保持展开。
5. 错误发生时自动展开并可见。
6. 桌面与窄屏均无横向溢出。
7. 现有补采、刷新、分页和来源状态逻辑不受影响。

## 验证方式

- 为折叠状态规则增加回归测试，并遵循先失败、后实现的测试驱动流程。
- 运行全量测试、TypeScript 类型检查、lint 和生产构建。
- 启动本地服务，在浏览器中验证默认收起、手动切换、运行时自动展开和窄屏布局。

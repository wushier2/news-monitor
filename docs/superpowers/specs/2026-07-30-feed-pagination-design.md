# 信息流页码分页设计

## 目标

为 G端资讯监控的信息流增加服务端页码分页，使用户能够浏览最近 7 天内超过当前 60 条展示上限的数据，并保持关键词、来源和自定义时间范围筛选的组合能力。

本次采用页码分页，每页固定展示 50 条。筛选条件变化、手动刷新或五分钟自动刷新后回到第 1 页。

## 范围

本次包含：

- Feed API 的分页参数和分页元数据。
- D1 的匹配总数查询和分页数据查询。
- 信息流底部的桌面端、移动端分页栏。
- 分页与关键词、来源、时间范围、刷新行为的组合。
- 将“今日新增”改为服务端真实统计，避免只统计当前页。

本次不包含：

- 修改四个来源每轮最多解析 50 条的采集规则。
- 无限滚动或“加载更多”。
- 用户自定义每页条数。
- 将分页状态写入 URL 或浏览器存储。
- 修改最近 7 天的数据保留规则。

## API 契约

`GET /api/feed` 增加以下查询参数：

- `page`：正整数，默认值为 `1`。
- `pageSize`：正整数，默认值为 `50`，允许范围为 `1` 至 `100`。当前页面始终传入 `50`。

非法参数处理：

- 非数字、小数、零和负数均返回 HTTP 400。
- `pageSize` 大于 100 返回 HTTP 400，不静默截断。
- 缺少参数时使用默认值。

响应保留现有 `items`、`sources` 和 `generatedAt`，并新增：

```json
{
  "items": [],
  "sources": [],
  "generatedAt": "2026-07-30T11:30:00.000Z",
  "todayCount": 42,
  "pagination": {
    "page": 1,
    "pageSize": 50,
    "totalItems": 236,
    "totalPages": 5
  }
}
```

字段语义：

- `todayCount`：所有来源中，自北京时间当天 00:00 起至当前时刻的有效信息总数，不受当前页、关键词、来源和自定义时间范围筛选影响。它代表顶部的全站“今日新增”状态。
- `totalItems`：符合当前关键词、来源和时间范围筛选条件的全部条数。
- `totalPages`：`Math.ceil(totalItems / pageSize)`；无匹配数据时为 `0`。
- 请求页码超过 `totalPages` 时，返回空 `items`、请求中的 `page` 和真实分页元数据，不自动改写页码。

## 数据查询

### 过滤条件

分页数据查询和总数查询共用同一组条件：

- 来源：`source_id = ?`。
- 关键词：标题或摘要的转义 `LIKE` 匹配。
- 时间范围：`COALESCE(published_at, first_seen_at)` 的开始包含、结束分钟包含规则。

### 总数与分页

仓储层返回一个结构化结果：

```ts
interface FeedPage {
  items: FeedItem[];
  totalItems: number;
}
```

查询流程：

1. 使用 `SELECT COUNT(*) AS count FROM items ...` 获取 `totalItems`。
2. 使用相同条件查询当前页，执行 `LIMIT ? OFFSET ?`。
3. `offset = (page - 1) * pageSize`。
4. 排序为：

```sql
ORDER BY COALESCE(published_at, first_seen_at) DESC, id DESC
```

`id DESC` 用于解决多条信息有效时间相同时的顺序不稳定问题。

### 今日新增

新增独立的仓储统计查询：

```sql
SELECT COUNT(*) AS count
FROM items
WHERE COALESCE(published_at, first_seen_at) >= ?
  AND COALESCE(published_at, first_seen_at) <= ?
```

边界使用北京时间当天 00:00 对应的 UTC 毫秒值和当前时刻。该统计不使用当前信息流筛选条件。

## 页面状态与请求

Dashboard 新增：

- `page`：当前页，初始为 1。
- `pageSize`：常量 50。
- `pageLoading`：分页请求状态。
- `pagination`：服务端返回的页码、总条数和总页数。

`requestFeed` 接收并发送 `page`、`pageSize`，同时继续发送关键词、来源和时间范围参数。

为了防止较慢的旧请求覆盖新条件下的结果，每次筛选请求使用递增请求序号。只有最后发出的请求可以写入 `feed`、`pagination` 和错误状态；卸载后的请求结果也不得写入状态。

## 重置规则

以下操作先将页码设为 1，再按新条件请求：

- 修改关键词。
- 切换来源。
- 应用时间范围。
- 清除时间范围。
- 手动刷新。
- 五分钟自动刷新。

首次进入页面请求第 1 页。

当用户只点击页码时，保留当前关键词、来源和时间范围。

## 分页栏

分页栏放在信息流列表之后、页面 footer 之前。

桌面端：

- 左侧显示 `共 236 条`。
- 中间显示“上一页”、页码按钮、“下一页”。
- 当前页使用既有深绿色强调色。
- 禁用按钮保持可辨识但不可点击。

页码窗口最多显示 5 个数字页码：

- 总页数不超过 5：显示全部页码。
- 靠近开头：显示 `1 2 3 4 … 最后一页`。
- 靠近末尾：显示 `1 … 最后四页`。
- 位于中间：显示 `1 … 当前页前一页 当前页 当前页后一页 … 最后一页`。

省略号为非交互文本，不是按钮。

移动端：

- 使用横向紧凑布局。
- 保留“上一页”、当前页附近的数字页码和“下一页”。
- 总条数独占一行或置于分页按钮上方。
- 不允许页面产生横向溢出。

显示规则：

- 没有数据时显示 `共 0 条`，不显示页码按钮。
- 只有 1 页时显示总条数，不显示页码按钮。
- 多于 1 页时显示完整分页导航。

## 交互行为

- 点击页码后立即进入加载状态，禁用所有分页按钮。
- 成功后替换列表内容，并将信息流标题滚动到视口顶部附近。
- 失败时保留原列表和原页码，显示“分页加载失败”，重新点击仍可重试。
- 第 1 页禁用“上一页”。
- 最后一页禁用“下一页”。
- 越界空页响应不会自动跳页；正常 UI 不会生成越界按钮。

## 错误处理

- API 参数错误返回 HTTP 400 和中文错误信息。
- 数据库或服务器异常返回 HTTP 500。
- 筛选请求失败继续使用现有通用错误区域。
- 分页请求失败不清空已显示列表，避免用户失去当前上下文。
- 刷新开始时以第 1 页为目标，但仅在刷新及第 1 页读取成功后提交新页码和列表。任一步骤失败都保留原列表和原页码；用户再次刷新时仍以第 1 页重试。

## 测试

### 输入与 API

- `page` 和 `pageSize` 默认值。
- 合法正整数。
- 非数字、小数、零、负数和超过 100 的 `pageSize`。
- API 返回 `pagination` 和 `todayCount`。
- 关键词、来源、时间范围与分页参数同时传递。

### 仓储层

- 总数查询和分页查询使用相同过滤条件。
- 50 条分页的第一页、中间页和末页。
- 越界页返回空数组和真实总数。
- 相同有效时间使用 `id DESC` 稳定排序。
- 今日新增按北京时间当天边界统计，且不受筛选条件影响。

### 页面逻辑

- 页码窗口在开头、中间和末尾的输出。
- 总页数为 0、1、5 和大于 5 的情况。
- 修改关键词、来源和时间范围后回到第 1 页。
- 手动刷新和自动刷新后回到第 1 页。
- 翻页保留全部筛选条件。
- 旧请求结果不能覆盖新请求结果。
- 分页失败保留原列表。

### 验收

- 全量测试通过。
- TypeScript 检查通过。
- lint 通过。
- 生产构建通过。
- 桌面端页码、总条数、禁用状态和滚动行为正确。
- 移动端无横向溢出。
- 本地 API 的第一页、末页、越界页以及组合筛选返回正确结果。

## 完成标准

- 用户能够通过页码浏览当前筛选条件下最近 7 天的全部已入库信息。
- 每页固定 50 条，分页总数准确。
- 筛选和刷新始终从第 1 页重新开始。
- 顶部“今日新增”不再受当前页 50 条限制。
- 已有采集、去重、时间筛选和七天保留规则不发生非预期变化。
